Critical findings

Critical Security

The product is not in version control — and the home directory is

The git repository root is the user's home directory, not the project. It tracks 50,215 files — caches, AI agent state, package stores — and not one file from the actual product.

  • No history, so no rollback.
  • No diff, so no code review.
  • No CI — a workflow file at the project root would simply be ignored.
This is the one thing to fix first. Nothing else on this page works properly until the project has its own repository.
Critical Security

Credentials are committed to a repository with a GitHub remote

These are tracked in a repository pushed to github.com/Enjoyer09/AZERIGIS:

PathWhat it is
.ssh/id_ed25519An SSH private key

.aws/sso/cache/…AWS SSO token
.docker/config.jsonDocker registry credentials

.claude.json, .gemini/AI agent configs — routinely hold API keys
The repository is private (verified), which is the only reason this is not already an incident. That protection disappears the moment it is made public, forked, or a collaborator's account is compromised.

Rotate every one of these credentials, then purge them from history. Deleting the files in a new commit is not enough — history is permanent.

The good news: a scan of first-party source found zero hardcoded credentials. The leak is entirely from the home-directory repository.
Critical Dead feature

A core feature has never worked: acknowledging a task from Telegram

The Telegram webhook built the acting user as a plain string and passed it where an authenticated principal object was required. The authorisation layer saw an undefined user and rejected every single call with 403.

The compiler reported this on two lines. Nothing ran the compiler, so nobody knew.

And it was also an authorisation hole. The actor identity came from the request body, which an attacker controls. Any Telegram account that knew a task id could have acted on it, and written itself into the audit log.

Fixed. Identity now comes from the Telegram-to-user mapping that already existed and was simply never called. An unregistered account is refused.
High Build integrity

The API was compiling against a stale build artefact

The API resolves its own workspace packages to compiled declaration files, not source. The compiled copy predated four methods, so the compiler believed they did not exist — producing 8 of the 19 errors out of thin air. Rebuilding made them vanish.

The real problem is that nothing enforces build order. The permanent fix is TypeScript project references, which makes the compiler refuse to use a stale declaration.

High Process

Tests were never type-checked, and that hid fourteen errors

The API's TypeScript config included only src/**. The test directory was therefore invisible to the compiler — which is how fourteen call sites that omitted a required argument survived unnoticed.

Security gaps closed in code

Fixed Webhook authentication

The Telegram webhook now verifies its sender

The endpoint is reachable by anyone who knows the URL, and it can move a task through its state machine and write to the audit log. It now requires Telegram's secret-token header, compared in constant time so the secret cannot be recovered by measuring response times.

It fails closed. If the secret is not configured in production, every request is refused rather than accepted unverified. "Secure when configured" is how a misconfiguration becomes a breach.

Six tests prove it: forged token rejected (401) · task state provably unchanged · missing header rejected · correct token accepted · unregistered Telegram account refused (403) · production-without-secret failing closed (503).

Fixed CORS

The API no longer accepts requests from any website

It previously answered origin: '*'. With bearer-token authorisation that means any page a signed-in user visits can call the API as them and read the responses — the token never has to leak.

It is now an explicit allow-list. A wildcard value is actively rejected, and production with no configured list refuses cross-origin requests and says so loudly in the log.

Fixed Identity

A request can no longer state who it is from

The evidence-submission request carried a submittedById field. The service ignored it and used the authenticated principal — but it was a trap: it invited exactly the mistake that caused the Telegram bug, and any future code that trusted it would be identity spoofing.

Removed from the request DTO, along with all ten call sites. The stored record keeps the field, because recording who actually acted is necessary for the audit trail. The rule is now enforced by the type system.

Fixed Build integrity

Stale build artefacts can no longer be compiled against

The API now uses TypeScript project references. The compiler refuses to use a declaration file that predates the source it describes, which permanently closes the class of bug described above.

Separately, strict type checking is now on for the API. It turned out to cost nothing — zero new errors. The code was already strict-clean; the flag was unnecessary caution that had been suppressing future guarantees.
