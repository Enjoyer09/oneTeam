2 Başlamazdan əvvəl bilməli olduğunuz 3 şey

2.1 · Kod hələ GitHub-da deyil

Railway kodu GitHub-dan oxuyur. Layihə hələ GitHub-da olmadığı üçün Addım 0 məcburidir.

2.2 · Veb panel hazırda demo məlumat göstərir

Veb panel məlumatı birbaşa Supabase adlı xarici xidmətdən oxuyur — API-dən yox. Supabase qurulmayıbsa, panel açılır və işləyir, lakin gördüyünüz bütün mağazalar, tapşırıqlar və yoxlamalar uydurma nümunə məlumatdır.

Bu normaldır

Test deploy üçün məqsəd «proqram onlayn işləyir» olduğunu görməkdir — demo məlumat bunun üçün kifayətdir. Real məlumat istəyirsinizsə, bu Bölmə 6-da əlavə addımdır.

2.3 · Şifrələr dəyişdirilməlidir

Köhnə docker-compose.prod.yml faylında sabit, hamıya məlum bir baza şifrəsi var idi (coca_cola_secret_2026). Bu artıq düzəldildi: indi şifrə verilməzsə sistem ümumiyyətlə işə düşmür. Aşağıdakı addımlarda öz şifrənizi yaradacaqsınız.

2.4 · Hazırda məlumat bazada saxlanmır — yaddaşda saxlanır

Bunu bilməyiniz vacibdir, çünki pul ödədiyiniz şeyə təsir edir.

Hazırda API və bot bütün məlumatı yaddaşda saxlayır. Nəticələr:

  • Servis yenidən başladıqda (deploy, restart, nasazlıq) bütün məlumat silinir.
  • Postgres bazası qoşulub işləyir, lakin heç bir proqram kodu ona qoşulmur.
  • Yeganə real baza yolu Supabase-dir — veb panel birbaşa oradan oxuyur.
Nəticə

«Hər şey bir yerdə» API, bot və veb panel üçün doğrudur. Məlumatın özü isə hələlik yaddaşdadır və ya Supabase-dədir. Test üçün normaldır; real istifadəyə keçməzdən əvvəl API-nin bazaya qoşulması ayrı bir işdir (Bölmə 6).

3 Addım-addım deploy

Sıra ilə gedin. Hər addım əvvəlkinin üzərində qurulur.

Addım 0 — Kodu GitHub-a yerləşdirin MƏCBURİ

Layihə qovluğu artıq git üçün hazırdır (ilk commit edilib). İndi onu GitHub-a göndərmək lazımdır.

Ən asan yol — GitHub Desktop:

  1. desktop.github.com ünvanından GitHub Desktop proqramını endirib quraşdırın.

  2. Proqramı açın və GitHub hesabınızla daxil olun.

  3. Yuxarı menyudan: File → Add local repository…

  4. Qovluq seçin: /Users/macbookair/GitHub/oneTeam

  5. Proqram «This directory does not appear to be a Git repository» yazsa, «create a repository» linkinə basın və Create repository düyməsini basın.

  6. Yuxarıda Publish repository düyməsini basın.

  7. Açılan pəncərədə: Name: oneteam · ☑ Keep this code private — bu işarəni mütləq qoyun.

  8. Publish repository düyməsini basın.

Niyə «private»?

Layihədə həssas məlumat ola bilər. Public repo = hamının gördüyü repo.

Addım 1 — Railway hesabı

  1. railway.com ünvanına gedin.

  2. Sağ yuxarıda Login düyməsinə basın.

  3. Login with GitHub seçin və icazə verin.

  4. Hesabınıza ödəniş kartı əlavə etməli olacaqsınız (Bölmə 4-ə baxın).

Addım 2 — Yeni proyekt yaradın

  1. railway.com/dashboard səhifəsinə gedin.

  2. Sağ yuxarıda + New Project düyməsinə basın.

  3. Empty Project seçin.

  4. Proyektin adını dəyişin: yuxarıdaki ada basıb oneteam-test yazın.

Boş bir «kanvas» görəcəksiniz. Servisləri bura əlavə edəcəyik.

Addım 3 — Verilənlər bazası (PostgreSQL)

  1. Kanvasda + New düyməsinə basın.

  2. Database → Add PostgreSQL seçin.

  3. Railway bazanı yaradır və adını Postgres qoyur.

Adı dəyişməyin

Servisin adı Postgres qalmalıdır, çünki növbəti addımlarda ona adı ilə istinad edəcəyik.

Ehtiyat nüsxə yoxdur

Railway-in bazaları «idarə olunmayan» (unmanaged) servislərdir — avtomatik backup yoxdur. Test üçün problem deyil; real istifadəyə keçəndə ayrıca qurulmalıdır.

Addım 4 — Backend (API) servisi

  1. Kanvasda + New → GitHub Repo seçin.

  2. Siyahıdan oneteam reposunu seçin.

  3. Servisin adını dəyişin: api

a) Dockerfile yolu — Settings → Build bölməsini açın. Dockerfile Path sahəsinə yazın:

apps/api/Dockerfile

b) Dəyişənlər — servisin Variables tabına keçin, sağ yuxarıda RAW Editor düyməsinə basın, aşağıdakı sətirləri olduğu kimi yapışdırın və <…> yerlərini öz dəyərlərinizlə dəyişin:

NODE_ENV=production
PORT=3001
DATABASE_URL=${{Postgres.DATABASE_URL}}
TELEGRAM_BOT_TOKEN=<BotFather-dan aldığınız token>
TELEGRAM_WEBHOOK_SECRET=<Bölmə 3.1-də yaratdığınız gizli açar>
CORS_ALLOWED_ORIGINS=https://<veb-panel-ünvanı>
SUPABASE_URL=https://mock-oneteam.supabase.co
SUPABASE_ANON_KEY=mock-anon-key
SUPABASE_SERVICE_ROLE_KEY=mock-service-role-key
  • ${{Postgres.DATABASE_URL}} hissəsini olduğu kimi saxlayın. Railway bunu avtomatik olaraq bazanın ünvanı ilə əvəz edir.
  • CORS_ALLOWED_ORIGINS — bunu Addım 5-i bitirdikdən sonra doldurun.

c) Ünvan yaratmaq — Settings → Networking bölməsini açın, Generate Domain düyməsinə basın. Port soruşsa: 3001

Bu ünvanı kopyalayın — Telegram botu bura müraciət edəcək:

api-production-xxxx.up.railway.app

Addım 5 — Veb panel servisi

  1. Kanvasda + New → GitHub Repo → yenə oneteam reposunu seçin.

  2. Servisin adını dəyişin: web

  3. Settings → Build → Dockerfile Path sahəsinə yazın: web/Dockerfile

  4. Variables tabına keçin. Bu dəyişənlər build vaxtı istifadə olunur (Vite onları fayllara «yazır»), ona görə düzgün adla yazılmalıdır:

    VITE_SUPABASE_URL=https://mock-oneteam.supabase.co
VITE_SUPABASE_ANON_KEY=mock-anon-key

    Supabase qurmasanız da bu iki sətri yazın. Boş qalsa panel yenə açılır, sadəcə demo məlumatla.

  5. Settings → Networking → Generate Domain. Port soruşsa: 80

  6. Bu ünvanı kopyalayın — bu, panelinizin linkidir. Komandaya göndərəcəyiniz link budur.

  7. İndi Addım 4-b-ə qayıdın və CORS_ALLOWED_ORIGINS dəyərini bu ünvanla doldurun:

    CORS_ALLOWED_ORIGINS=https://<burada-panel-ünvanı>
Niyə bu lazımdır?

Təhlükəsizlik üçün API yalnız icazə verdiyiniz ünvandan gələn sorğuları qəbul edir. Ünvanı yazmasanız, brauzerdən heç bir sorğu keçməyəcək.

Addım 6 — Telegram bot servisi İSTƏYƏ BAĞLI

Bunu atlaya bilərsiniz

Yalnız paneli görmək istəyirsinizsə, birbaşa Addım 7-yə keçin. Botu atlamaq aylıq xərci də azaldır.

  1. + New → GitHub Repo → oneteam. Servisin adı: bot

  2. Settings → Build → Dockerfile Path: Dockerfile.bot

  3. Variables:

    NODE_ENV=production
TELEGRAM_BOT_TOKEN=<BotFather-dan aldığınız token>
DATABASE_URL=${{Postgres.DATABASE_URL}}
API_BASE_URL=http://api.railway.internal:3001
SUPABASE_URL=https://mock-oneteam.supabase.co
SUPABASE_ANON_KEY=mock-anon-key

    http://api.railway.internal:3001 — bu, Railway-in daxili şəbəkə ünvanıdır. api servisin adıdır, 3001 isə onun portu. Dəyişməyin.

  4. Bu servisə ünvan (domain) lazım deyil. Bot özü Telegram-a qoşulur.

  5. Telegram-a webhook-u bildirin. Terminal açın və yapışdırın (<TOKEN> və <API-ÜNVANI> yerlərini doldurun):

    curl -X POST "https://api.telegram.org/bot<TOKEN>/setWebhook" \
     -d "url=https://<API-ÜNVANI>/api/notifications/telegram/webhook" \
     -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>"

    Cavabda {"ok":true, ...} görməlisiniz.

Addım 3.1 — Gizli açarı yaratmaq

Terminal açmaq üçün: Cmd + Space basın, Terminal yazın, Enter.

Terminalda bu əmri yapışdırıb Enter basın:

openssl rand -hex 32

Ekranda 64 simvollu təsadüfi bir mətn çıxacaq, məsələn:

9f3a7c1e5b8d2046a1c9e7f3b5d8024e6a9c1f7b3d5e8024a6c9f1b3d5e7a902

Bu mətni kopyalayın. Bu, TELEGRAM_WEBHOOK_SECRET dəyəridir. Onu:

  • Addım 4-də API servisinin dəyişənlərinə,
  • Addım 6-da botun webhook əmrində secret_token= hissəsinə

yazacaqsınız. Hər iki yerdə eyni olmalıdır.

Niyə bu lazımdır?

Telegram webhook ünvanını bilən hər kəs saxta sorğu göndərə bilər. Bu açar olmadan API heç bir webhook-u qəbul etmir — bu, qəsdən belədir.

Addım 7 — Yoxlama

7.1 · Servislərin işə düşdüyünü yoxlayın
Kanvasda hər servisin üzərindəki rəngə baxın: yaşıl = işləyir, qırmızı = xəta. Qırmızıdırsa, servisin üzərinə basıb Deploy Logs bölməsindəki son 20 sətri oxuyun.

7.2 · Veb paneli yoxlayın
Brauzerdə panel ünvanını açın. Gözlənilən: mağazalar, tapşırıqlar və yoxlamalar olan idarəetmə paneli açılır.

7.3 · API-ni yoxlayın
Brauzerdə API ünvanının sonuna /api/health əlavə edin:

https://<api-ünvanı>/api/health

Gözlənilən cavab:

{ "status": "ok", "service": "oneteam-api", "uptimeSeconds": 42, "timestamp": 1789306800000 }
Diqqət

/api/tasks ünvanını açsanız 401 Unauthorized görəcəksiniz. Bu xəta deyil — tapşırıq siyahısı giriş tələb edir və 401 girişin işlədiyini sübut edir. Yoxlama üçün /api/health istifadə edin.

7.4 · Botu yoxlayın
Telegram-da botunuza girib /start yazın. Cavab gəlməlidir.

6 Sonrakı addımlar (test-dən sonra)

  1. API-ni real bazaya qoşmaq. Ən böyük boşluq budur. packages/database hazırda yaddaşdaki SEED_DATA-dan istifadə edir; DATABASE_URL dəyişəni heç oxunmur. Yəni baza qoşulub işləyir, amma heç bir kod ona müraciət etmir. Bu, kod dəyişikliyi tələb edir və ayrı bir işdir.

  2. Real Supabase bazası. supabase.com-da pulsuz layihə açın, Settings → API bölməsindən URL və anon key götürün. Sonra:

    • web servisinin VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY dəyişənlərinə,
    • api servisinin SUPABASE_URL / SUPABASE_ANON_KEY dəyişənlərinə yazın.

    Sonra supabase/migrations qovluğundaki SQL fayllarını Supabase-də işə salın.

  3. Ehtiyat nüsxə. Railway bazası avtomatik backup etmir. Gündəlik dump qurun.

  4. Şifrələrin rotasiyası. TELEGRAM_BOT_TOKEN və TELEGRAM_WEBHOOK_SECRET dəyərlərini mütəmadi dəyişin.

  5. Domen. Öz domeninizi qoşun (Settings → Networking → Custom Domain).
